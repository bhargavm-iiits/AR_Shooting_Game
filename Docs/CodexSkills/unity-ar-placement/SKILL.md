# Unity AR placement

## Configure the scene

1. Read the project's Unity version, package manifest, and active Android quality profile. Install a matching released pair of AR Foundation and Google ARCore XR Plugin versions for that editor. Enable Google ARCore under Android in XR Plug-in Management and resolve the Android Project Validation errors. For a game that can run without AR, set ARCore Requirement and Depth to Optional. Use OpenGLES3 as the compatibility baseline when it is supported by the chosen version. [Unity ARCore project configuration](https://docs.unity3d.com/Packages/com.unity.xr.arcore@6.5/manual/project-configuration-arcore.html)
2. Set up one `ARSession` and one unit-scale `XR Origin (Mobile AR)`. Put `ARPlaneManager`, `ARRaycastManager`, and `ARAnchorManager` on the origin. Use the AR Camera's tracked pose, `ARCameraManager`, and `ARCameraBackground`. Add `ARBackgroundRendererFeature` to the Universal Renderer actually selected by that camera and Android quality profile. Leave depth occlusion and CPU camera image access off unless the feature needs them. [AR Foundation URP setup](https://docs.unity3d.com/Packages/com.unity.xr.arfoundation@6.5/manual/project-setup/universal-render-pipeline.html)
3. Give the placement controller explicit references to the managers, active camera, and arena prefab. Make the arena's local origin its bottom-center contact point, with local `+Y` up and scale one. Parent the model corrections and target spawn sockets under that root so every mode uses the same prefab at meter scale.

## Gate startup by capability

1. Keep the AR scene rig inactive until startup accepts the device. Make Practice Mode accessible while checking AR availability and when the check fails. Wait for the configured Android XR loader to initialize, then run the `ARSession.CheckAvailability()` coroutine and inspect `ARSession.state`. For manual loader control, initialize it through XR Plug-in Management before probing. Treat a missing loader, unsupported device, and a check that stalls as distinct outcomes in the UI and logs. [ARSession API](https://docs.unity3d.com/Packages/com.unity.xr.arfoundation@6.5/api/UnityEngine.XR.ARFoundation.ARSession.html) [XR loader lifecycle](https://docs.unity3d.com/Packages/com.unity.xr.management@4.5/manual/EndUser.html)
2. On entering AR, check service availability again. Call `ARSession.Install()` from the explicit AR flow when the state is `NeedsInstall`, then wait for a usable state before enabling the AR session. Use one owner for installation prompts. Request or check Android camera permission only in the AR flow and activate the AR camera after permission is granted. Handle install cancellation, failed updates, permission denial, and permission revoked in Settings with a clear reason and the Practice Mode choice. Verify the merged APK manifest has optional AR metadata, camera permission, and no required AR camera feature. [Google AR Optional behavior](https://developers.google.com/ar/publish)
3. Run practice using a normal Unity camera at a fixed position with drag-to-aim rotation, a virtual ground plane, and no camera permission dependency. Keep a persistent `PRACTICE MODE` label. Use the same arena prefab, projectile physics, target behavior, score, and completion logic, passing the practice camera into the shared gameplay controller. Start a fresh round when switching modes and release the departing rig's resources. Keep exactly one gameplay camera and one `EventSystem` active.

## Place exactly once per round

1. Set `ARPlaneManager.requestedDetectionMode` to `PlaneDetectionMode.Horizontal`. Draw a subtle visualization of the detected plane bounds while scanning and display a placement hint when a usable plane exists. When a single tap ends outside interactive UI, raycast from its screen position with `TrackableType.PlaneWithinPolygon` into a reused results list. Resolve each hit to a live `ARPlane` by its trackable ID. Select the nearest tracked, unsubsumed `HorizontalUp` hit. Preserve scanning on a miss, a wall, or a UI tap. With the Input System, perform an explicit UI raycast at the touch position or query pointer state after the UI module updates. Keep decorative graphics from intercepting taps. [AR raycast manager](https://docs.unity3d.com/Packages/com.unity.xr.arfoundation@6.5/api/UnityEngine.XR.ARFoundation.ARRaycastManager.html)
2. Build the anchor's world pose from the hit point and the plane normal (`plane.transform.up`). Project the desired heading onto the plane and use it with the normal in `Quaternion.LookRotation`. Use the plane's forward axis if the projected heading is near zero. Set the pose before requesting the anchor. Keep the arena local position and rotation at zero and identity under the accepted anchor. The bottom of the prefab should touch the real surface without an offset applied in placement code.
3. Move from scanning to placing before the first `await` so fast taps cannot start multiple requests. With AR Foundation 6.5, await `ARAnchorManager.TryAddAnchorAsync(pose)` and check `result.status.IsSuccess()` and `result.value`. Capture a round/session generation before the call. A reset, mode change, or teardown invalidates pending work. Release anchors from stale results through the manager when available. On failure or a bounded tracking timeout, release any unusable anchor and restore scanning with retry feedback. Instantiate the arena once after the accepted anchor is tracking, report the arena root and active camera to gameplay, and hide scan visualization. Keep the anchor manager active and leave the accepted anchor transform under provider control. [Anchor creation and lifecycle](https://docs.unity3d.com/Packages/com.unity.xr.arfoundation@6.5/manual/features/anchors/aranchormanager.html)

## Recover tracking and verify on hardware

- Gate placement on `ARSessionState.SessionTracking` and firing on both session and placed-anchor tracking. During limited tracking or backgrounding, block new placement and firing, remove in-flight shots without scoring, and preserve the existing round and anchor. Show actionable tracking feedback for low light, fast motion, and low-detail surfaces. Restore play when the existing anchor tracks again. If the anchor is removed or fails to recover, offer an explicit restart that clears the old anchor, round, and pending requests before rescan.
- On a certified Android phone, verify a textured table and floor in good light, a tap outside bounds, a UI tap, rapid double taps, and a walk around the placed arena. Check surface contact from a low angle and confirm the same arena survives temporary tracking loss and app resume. Test slow detection in dim light without blocking the practice choice. On an Android device without ARCore support, test that practice opens and the full round can be completed without camera permission. Also test camera denial and the service-install path when available. Record tested model, OS, service version, and outcome. Report editor simulation separately from physical tracking. [ARCore certified device list](https://developers.google.com/ar/devices)
